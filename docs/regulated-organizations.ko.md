# 규제 조직에서 리펜 쓰기

[English](regulated-organizations.md) · 한국어

> 이 문서는 리펜 설정에 대한 일반 정보이며 법률 자문이 아닙니다. 로펌·병원·공공
> 기관이 의뢰인·환자·시민에게 지는 의무는 나라와 직역마다 다릅니다. 이 문서에
> 기대기 전에 자기 법률 자문과 감독 기관에 확인하세요.

자료를 밖에 둘 수 없는 조직이 있습니다. 의뢰인 서류를 가진 로펌, 진료 기록을
가진 병원, 시민 정보를 가진 공공 기관입니다. 이 문서는 그런 조직이 리펜과 구성원이
쓰는 에이전트를 들일 때 자료가 어디에 머물고, 어떤 모델이 읽고, 에이전트가 어디까지
닿고, 의뢰인을 어떻게 손님으로 들이고, 무엇이 기록되는지를 각 설정의 이름과 위치로
정리합니다.

## 1. 서버는 직접 둡니다

리펜은 직접 운영하는 서버에서 돕니다([셀프호스팅](self-hosting.md)). 페이지,
데이터베이스, 파일과 기록은 그 서버와 백업에 남습니다. 사람과 서버 사이에
리펜의 서비스가 끼지 않습니다. 규정이 허락하는 곳 — 사무실, 자기 클라우드 계정,
자기 나라 — 에 두고 백업도 그곳에 둡니다.

## 2. 모델이 어디서 읽는지 고릅니다

리펜은 자체 모델을 돌리지 않습니다. 에이전트는 바깥에서 — Claude, ChatGPT, Codex,
Claude Code나 직접 돌리는 모델 — MCP로 들어오고, 에이전트는 일하는 것 — 페이지,
의뢰인 파일, 질문 — 을 자기 모델에 보냅니다. 자료가 어디로 가는지는 그 모델이 어디서
도는지가 정합니다. 자기 컴퓨터나 서버의 모델이면 아무 데도 가지 않고, 데이터를 남기지
않는(ZDR) 클라우드 모델이면 제공자에게 가되 남지 않고, 그 밖에는 제공자의 보통 조건으로
갑니다.

설정 → 신원 → **엔터프라이즈 관리 연결**에서 어떤 에이전트가 연결할 수 있는지
정합니다. **승인된 MCP 클라이언트만**을 켜고 승인한 클라이언트만 두면 다른
클라이언트와 그 토큰은 모두 막힙니다.

클라우드 모델이 의뢰인 자료를 읽으면 그 제공자가 처리하고, 흔히 다른 나라에서
처리합니다. 그때는 대부분의 규정이 요구하듯이:

- **의뢰인에게 알립니다** — 수임 계약서, 동의서, 개인정보 처리방침에 — AI 서비스가
  그 자료를 처리한다는 것, 어느 서비스인지, 어느 나라인지.
- **처리 위탁 계약을 맺습니다**(데이터 처리 계약, 위탁 계약). 데이터를 남기지 않는
  조건에 기대면 그것도 적습니다.
- **국외 이전 규정을 확인합니다.** 나가면 안 되는 것(일부 기록, 일부 비밀 자료)도
  확인합니다.

## 3. 에이전트가 닿는 곳

에이전트의 연결은 그 사람의 권한으로만 일합니다. 그 사람이 못 여는 것은 에이전트도
못 엽니다. 연결은 그 사람이 준 워크스페이스에만, 고른 범위(읽기·콘텐츠·구조·관리)로만
닿고, 그 사람은 Notion의 연결처럼 연결을 보고 끊습니다. 그 밖에 에이전트를 붙잡는 것:

- 설정 → 엔터프라이즈 제어 → **데이터 유출 방지**: 페이지·행·댓글·파일을 쓸 때 민감
  용어를 검사하고, **웹 공개 공유 차단**, **외부 공유 차단**, **파일 다운로드 차단**,
  **내보내기 차단**을 켭니다.
- 설정 → 보안 → 멤버 및 게스트: **페이지에 게스트를 초대할 수 있는 사용자**를
  정합니다. 설정 → 보안 → 일반 → 보기 링크: **비밀값 없는 보기 링크 허용**을 꺼서
  보기 링크에 따로 보낸 비밀값이 함께 필요하게 합니다.

의뢰인은 자기에게 공유된 것만 봅니다(아래). 리펜은 손님이 보기 전에 바뀐 내용을
승인 대기로 붙잡지 않으므로, 의뢰인 앞에 무엇을 내놓는 단계는 사람이 맡습니다.
에이전트는 조직 안 페이지에서 초안을 쓰고, 사람이 다 된 것을 의뢰인 쪽으로 옮기거나
공유합니다.

## 4. 의뢰인은 게스트로

의뢰인은 게스트로 초대합니다. 게스트는 자기에게 공유된 페이지만 보고, 워크스페이스의
나머지는 보지 못합니다. 누가 무엇을 보는지는 노션과 같은 도구로 정합니다.

- **팀스페이스.** 업무 그룹이나 사건마다 페이지를 자기 팀스페이스에 둡니다(설정 →
  팀스페이스 → 새 팀스페이스). **참가 제한**은 워크스페이스의 다른 사람이 볼 수는 있어도
  참가하지 못하고, **비공개**는 멤버가 아닌 사람에게 있다는 것조차 보이지 않습니다 —
  서로의 사건을 보면 안 되는 사람들 사이의 벽입니다. 사람은 한 명씩이나 **그룹**(설정 →
  사람 → 그룹)으로 넣습니다.
- **공유.** 페이지의 공유 메뉴에서 의뢰인에게 그 페이지의 수준 — 읽기, 댓글, 편집 — 을
  주면, 노션의 하위 페이지가 상위 페이지의 공유를 따르듯 그 아래 페이지도 함께
  갑니다. 페이지를 의뢰인과 공유하면 의뢰인은 조직의 게스트가 됩니다.
- **페이지 수준 사용 권한.** 데이터베이스의 공유 메뉴 → 페이지 수준 사용 권한 →
  "새 규칙 추가"로 사람 속성에서 선택된 모든 사람에게 자기 페이지의 권한을 줍니다.
  예를 들어 의뢰인마다 자기 이름이 든 사건만 봅니다.
- **속성 사용 권한.** 속성 메뉴 → 속성 사용 권한으로 목록에 없는 사람에게서 속성(수임료,
  내부 메모)을 가립니다. 모든 보기, 내보내기와 에이전트의 읽기에 적용됩니다.

## 5. 무엇이 기록되는가

- **편집.** 모든 편집은 페이지의 버전 기록과 워크스페이스 업데이트에 남고, 에이전트의
  편집에는 그 사람의 이름과 연결의 이름이 붙습니다.
- **감사 로그**(설정 → 조직, 소유자와 규정 준수 관리자): 권한 주고 거두기, 공유,
  멤버와 게스트, 페이지 수준 규칙, 로그인, 키와 연결을
  사람·기간·종류·대상으로 걸러 보고 CSV로 내보냅니다. 멤버의 **활동 이력**은 멤버
  표의 "이력"이나 프로필에서 열고, 각자는 설정 → 계정에서 자기 **로그인 기록**을
  봅니다.
- **열람 기록.** 서버가 내주는 모든 페이지·항목·파일 — 앱, API, 에이전트, 공유 링크,
  내보내기 — 이 누가 언제 어떻게 읽었는지와 함께 기록됩니다. 페이지의 ⋯ 메뉴 →
  **열람 기록**이 그 페이지와 그 아래 모든 것의 열람을 그곳의 전체 권한자에게 보여
  줍니다. 규정 준수 관리자는 페이지와 그 아래 모두에 대해 **열람 기록을 볼 사람**을
  "규정 준수 관리자만"으로 할 수 있습니다. 열람 기록은 서버 관리자만 서버 전체에서 끌 수 있습니다
  (설정 → 서버 → 감사 로그 → 열람 기록). 켜 두세요.
- **페이지 애널리틱스의 조회한 사람**(설정 → 조직, 감사 로그 아래): "사람마다 정함"은
  노션의 "내 조회 기록 표시"와 같고, "모두 보임"은 아무도 자기 조회를 숨기지 못하며
  (로펌의 선택), "모두 숨김"은 조회수만 보입니다(윗사람의 열람이 직원에게 보이지 않아야
  하는 곳). 열람 기록은 어느 쪽이든 모두 남습니다.
- **보관 기간.** 설정 → 엔터프라이즈 제어 → **감사 로그** → **감사 로그 보존**은
  감사 로그와 열람 기록을 지우지 않거나(바꾸지 않으면 이쪽), 정한 일수(1일 이상)가 지난
  것을 지웁니다. 같은 곳의 **법적 보존**은 보존이 덮는 것을 지우지 못하게 합니다.

## 짧은 점검표

1. 규정이 허락하는 곳에 서버와 백업을 둡니다.
2. 승인된 MCP 클라이언트만 두고, 에이전트는 자기 모델이나 데이터를 남기지 않는 모델로
   쓰며, 클라우드 모델을 쓰면 의뢰인에게 알리고 처리 위탁 계약을 맺습니다.
3. 연결은 일에 필요한 워크스페이스와 범위로만 줍니다.
4. 데이터 유출 방지를 민감 용어와 함께 켜고, 보기 링크는 비밀값과 함께만 씁니다.
5. 업무 그룹은 참가 제한이나 비공개 팀스페이스에 두고, 의뢰인은 공유한 페이지의
   게스트로 들이며, 내부의 것은 페이지 수준 규칙과 속성 사용 권한으로 가립니다.
6. 감사 로그는 규정 준수 관리자가 맡고, 열람 기록은 켜 두며, 볼 사람과 조회한 사람
   표시를 정하고, 보관 기간과 법적 보존을 정합니다.
